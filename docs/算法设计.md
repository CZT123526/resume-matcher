## 1. 统一抽取 Schema（7 类实体）

BERT NER 的输出、entities 表的 field_key、前端展示共用这一套字段，**任何一方不得私加字段**：

| field_key | 含义 | 规范化规则 | 示例 |
|---|---|---|---|
| `name` | 姓名 | 原样保留，长度 2~4 优先 | 张三 |
| `degree` | 学历 | 枚举归一：`大专/本科/硕士/博士`（别名表见 ner_rules；判不出的值直接丢弃，不再归一为"其他"——T29.2：实体必须有原文依据） | 硕士 |
| `school` | 毕业院校 | 原样保留（别名归一留给 P2，不做有损处理） | 华中科技大学 |
| `skill` | 技能 | 小写、去空格；同义合并（py→python） | python |
| `years` | 工作年限 | 归一为数字字符串（"三年"→"3"） | 5 |
| `company` | 任职公司 | 去括号备注；校名结尾的值丢弃（教育机构被 BERT 误标成公司——T30.3） | 腾讯 |
| `title` | 职位 | 原样保留；去 BERT 插入空格；政治面貌/语言等级黑名单丢弃（T30.2）；**项目栏目与项目头行（破折号+竖线+日期段）里的 title 标注丢弃**——项目名/项目内角色不是求职岗位（T30.3）；求职意向行无已知后缀时按锚定模式抽取 | 后端开发工程师 |

- 同一字段多值时输出多条记录（如多个 `skill`），不做合并存储。
- NER 没抽到的字段**不输出**空记录。

## 2. NER 方案（S02/S03）

### 2.1 标注体系

- 标注格式：**BIO**，标签集 = 7 实体 × {B,I} + O = 15 个标签。
- 数据集：公开**中文简历 NER 标注集**为主（约 3000 份简历、句级样本数万条，满足"训练样本 ≥ 1 万"口径——口径按**句级训练样本**计，不是简历份数）。
- 数据集标签 → 本项目 7 字段的映射表在 `backend/tools/data/label_mapping.py` 中以字典显式维护，映射不到的标签丢弃并记录丢弃数。
- CLUENER2020（约 1.2 万条）：**不做标签迁移**（实体体系与简历域不同），仅可选用于底座继续预训练；时间不够直接放弃，不阻塞主线（见 technical.md D7）。

### 2.2 长文本处理

简历全文远超 BERT 上限，采用**句级流水线**：

1. 训练：简历按行/标点切句，句级 BIO 标注，`max_len=256`；
2. 推理：同样切句逐批编码，实体按 `(句id, 字段)` 聚合，同字段同值去重；
3. 合并（T35 修订）：BERT 优先、字段级规则兜底；**例外——「求职意向/应聘岗位」显式字段行的 title 不受字段覆盖限制**，值级去重后强制并入。动机：BERT 常把证书/工具词误标成 title（有据但字段错），只要它产出过任意 title，字段级兜底就会把求职意向这条最准的岗位信号整体挡掉——口语化简历（证书行密集）上高发，症状是结构化文本里连求职岗位四个字都没有。

### 2.3 训练配置（Colab T4 实测可承受）

| 项 | 值 |
|---|---|
| 底座 | bert-base-chinese |
| 任务头 | 线性分类头（token 级，num_labels=15） |
| 优化器 | AdamW，lr=2e-5 |
| batch / epoch | 16 / 4 |
| max_len | 256 |
| warmup | 前总步数 10% 线性 warmup |
| 随机种子 | 42（写死，保证可复现） |
| 产物 | `backend/models/ner/`（不入库，.gitignore） |

### 2.4 指标口径

**实体级精确匹配**：预测实体的 `(字段, 值, 文本位置)` 全对才算 TP。

- P = TP / (TP + FP)，R = TP / (TP + FN)
- F1 = 2·P·R / (P + R) = 2·TP / (2·TP + FP + FN)

报告 P/R/F1 三个数。

## 3. 语义匹配（S05/S06）

### 3.1 编码对象

| 对象 | 编码文本 |
|---|---|
| JD | S04 抽出的要求 + JD 原文前 500 字，拼接 |
| 简历 | **结构化拼接文本**（v2，T36 B3）：实体清单（技能 + 职位 + 公司 + 学历 + 经验年限，由 entities 表拼接）+ **工作经历要点行**（原文中编号要点/工作动词句，预算 400 字符截断），不用全文 |

> 理由：全文含大量噪声（格式、联系方式）；结构化拼接让匹配对齐"岗位要求 ↔ 能力事实"。但 T32 实测纯实体清单语义分过薄（不同工种挤在 0.95~0.97），口语化简历的辨析信息藏在经历句里（"负责直播带货全流程" vs "负责剪辑成片"）——v2 把要点行补回编码文本，语义与词面（§3.2b 同源核查）同时受益。表示格式版本计入向量缓存指纹（`REPR_VERSION`，§3.3），格式变更自动触发全量重建。

### 3.2 向量与相似度

- 底座：同一个微调后 BERT（D5，NER 底座复用），取**最后层 mean pooling**（[CLS] 作为消融实验项）；
- 向量 L2 归一化后，余弦相似度 `cos ∈ [-1,1]`，线性归一 **`score = (1 + cos) / 2 ∈ [0,1]`，保留 4 位小数**；

### 3.2b 关键词重排层（T34，`svc/lexical.py` + `hybrid_rank`）

**动机**：T32 实测 BERT 语义分在同家族工种间聚集（跨度仅 ~0.01，Java 岗 top1 曾是 Python 简历），需要词面证据拉开区分度。

- **词面分**：JD 关键词 = `req.skills`（S04 → match_skills，简历/JD 同一词典）+ 标题内容词（剥通用后缀；中文段全由通用词拼成时丢弃，含内容词的整段保留，如「大数据开发」）。词面分 = 关键词在**简历匹配文本**（与编码同源 structured_text）中的命中率，ASCII 词带边界（java ≠ javascript、.net ≠ asp.net）；JD 无关键词时恒为 0.5（中性，不扭曲语义排序）。T35 修订：S04 技能抽取**先遮蔽行首职责标签再匹配**（"1、数据分析：每日盯店铺…"里的"数据分析"是栏目名不是技能要求），防职责栏目名混进关键词反向污染词面分。
- **融合**：`final = α·语义分 + (1-α)·词面分`，α 可配（`MATCH_ALPHA`，默认 0.7）。α=1.0 退化为纯语义（消融对照路 cosine_rank 保留）。
- **红线不变**：词面分属于打分侧；证据链（§4）依旧只解释不打分。词面分必须对全部简历算完再融合（top-k 截断之前），否则语义分挤掉的正确候选人永远进不了候选集。
- **金标准实测**：v2.1（112 简历×21 查询）纯语义 0.5759 → 融合 0.9043；v3（312 简历×36 查询）纯语义 0.5050 → 融合 0.9201；**v4（T36，1062 简历×46 查询千级语料，结构化文本 v2 表示）纯语义 0.7483 → 融合 0.9305**——语料扩到 3.4 倍后两路同时提升（B3 表示增强让纯语义从 0.5050 回升 0.7483，经历要点补回辨析信息）。α 扫描 0~0.9 全持平于 0.9305、α=1.0 精确退化纯语义（自洽校验）：v2 表示下词面信号已足以独立解题（纯词面 a=0.0 同为 0.9305），语义分的价值在于**非词面场景的保障**（同义改写、无关键词 JD）与编码器升级空间（§7.1 对比微调）。局限如实说明：α 在评测金标准上扫描选定（近似开发集调参）；模板语料各角色词面区分度高，对词面分有利；改写压力考卷（§7.2）实测正文避开岗位词时重排层转为轻微拖累（0.8774→0.8400），进一步印证语义分是词面失效场景的保障、词面分是模板语料的功臣。
- **自适应 α（T39/B2，`coverage_from_scores` + `adaptive_alpha`，env 开关 `MATCH_ADAPTIVE_ALPHA` 默认开）**：§7.2 拖累问题的制度化对策——词面**覆盖率** = 该 JD 关键词命中率 ≥0.5 的简历占池比（0.5 即无关键词中性值，只数"真有词面证据"的份），`α_eff = base + (1-base)·(1-coverage)`：覆盖满格 α_eff=base（词面证据普遍可得时行为不变），覆盖归零 α_eff=1.0 纯语义（词面分整体失效时不再放大噪声），中间线性过渡、**零自由参数**（阈值 0.5 沿用 keyword_hit_score 中性值约定，线性形状无超参）。默认**开**：三池验证全部向好（§7.4，v4 0.9305→0.9522 / 压力 0.8400→0.8589 / 半规范 0.9592→0.9826），置 0 可回到冻结口径；离线评测 harness（run_experiments.py）保持固定 α 不动，冻结数字不受影响。验证脚本 `tools/eval/adaptive_alpha_check.py`（v4 池 = 全库 − 压力 − 半规范 manifest 精确重建 1062 份，固定 α 复现 0.9305/0.8400 双断言通过——重建池=冻结池才允许谈开关）。诚实口径：方向由压力卷拖累现象启发（先看现象后定规则），但规则本身未在金标准上调任何参数。

### 3.2c 反向推荐校准（T39/B1，`svc/recommend.py`）

反向推荐（简历 → Top-K 岗位）复用正向的全套组件（编码对象 §3.1、查询编码器、向量主缓存、关键词抽取、证据链），但评分语义不同：正向是 **JD 内部排人**，反向是**跨 JD 比较**——裸余弦分带每岗位各自的基线与离散度（宽泛岗给谁都 0.98+，T32 分数聚集的镜像），裸词面命中率在关键词稀疏的岗上虚高（实测「网络工程师」只抽出 1 个关键词白拿 1.0，Java 岗 8 词命中 0.5 反而吃亏；直接融合会把 Java 简历推去「网络工程师」）。对策是**双侧校准**：

- **语义侧**：`semantic_percentile` = 简历语义分在该岗位**全池分布**中的百分位（"比池里 X% 的人更像本岗"），消除跨岗位基线差；
- **词面侧**：命中率向中性 0.5 收缩，`lex_cal = 0.5 + (hit−0.5)·min(1, n_kw/3)`——关键词 <3 个按 n/3 折扣（证据不足少说话），≥3 个全额；
- **融合**：`score = α·percentile + (1−α)·lex_cal`，α 沿用 `MATCH_ALPHA`；Top-K 截断在全部 JD 融合之后（红线同 §3.2b）。

正向链路零改动（JD 内部排序对单调变换不敏感，校准只在跨 JD 比较时必要）；接口契约见 backend-api.md §1（API-17），分数与正向匹配**不可直接比较**。JD 向量按内容指纹（编码器指纹 + 文本 md5）做进程内缓存，55 条 ≈ 2s 首建后毫秒级。

### 3.3 向量缓存（vectors.npy）

- 文件：`db/vectors.npy`（矩阵，行序对应 `db/resume_ids.json` 的 resume_id 列表）；
- 缓存指纹 = 编码器身份（BERT_MODEL_PATH / FORCE_TFIDF）+ **表示版本 `REPR_VERSION`**（T36 B3：结构化文本格式变化必须换版本，否则内容哈希不变会静默沿用旧表示的向量）；
- 重建规则（T41 起分两级）：
  - **增量重建（BERT 模式）**：哈希未变的简历**直接复用旧向量行**，只编码新增/删除/内容变化的简历——千级语料上原"任一变化全量重编"（CPU 约 100 秒/次）是匹配耗时主因，增量后常规匹配秒级；哈希对象为 **structured_text 的 md5**（编码输入本身），实体重抽不改原文也能正确失效；
  - **全量重建（其余）**：TF-IDF 模式（词表/IDF 依赖全语料，增量插入会改变特征空间）、编码器/表示版本指纹变化、首次建库——万级简历 CPU 重编码 < 10 分钟；
- 重建入口在解析流水线末尾与匹配任务（双重检查锁），等锁期间已重建则直接复用。

## 4. 证据链规则（S07）——打分与解释分离

**红线：证据链只解释分数，绝不参与打分。** 否则规则改动会污染三组模型的对比公平性。

```
输入: jd_reqs = S04(JD), ents = S02(简历)
输出: evidence[] (文本数组，文案格式定稿如下，前端原样展示)

1. 技能交集: S_jd ∩ S_resume
   → 非空: "技能重叠：Python/FastAPI (2/2)"
   → jd 有简历无: "缺少技能：Docker"
2. 学历比较: rank(degree) ∈ {大专0, 本科1, 硕士2, 博士3}
   → 满足: "学历满足：硕士≥本科" / 不足: "学历不满足：本科<硕士" / 缺失: "学历：未识别"
3. 年限比较: years(简历) ≥ min_years(JD)
   → "经验满足：5年≥3年" / "经验不足：1年<3年"；任一侧认不出则整行不出现（T49：
     库内简历原文无显式年限句式，「经验：未识别」占位无信息量，已删除）

格式约定: 全角冒号；计数用 (n/m)；比较式直接给结论。
```

## 5. 金标准构造（评测 ground truth，D6；T32 升级 v2，T33 人工校准 v2.1）

简历库自带的期望岗位信号是免费的监督标签，按简历类型取可靠来源：

1. **正样本对**（rel=1，判定依据按简历类型分路径）：
   - **模板简历**（文件名「姓名_角色.docx」可解析）：用**文件名角色**判定——角色是批量生成器写入的真实岗位元数据，比 NER 实体可靠（T32 抽检发现实体层混有"负责人/软件设计师"等噪声，且"Python 后端"的语言前缀在实体中丢失）；
   - **其他简历**（真实上传）：沿用职位实体匹配（v1 行为）。
   - 匹配判定三层递进（v2.1）：①核心语义相等；②互含且短核心带个性词（java ⊂ java后端）——**技术栈冲突否决**兜底（残留互斥如 python vs java 判不匹配）；③互含但短核心纯通用（数据 ⊂ 大数据）——必须过**细分白名单**（`_SPECIALIZATION`：算法→大模型/推荐…、前端→react/vue…），杜绝"数据分析师×大数据开发""测试开发×渗透测试"同家族不同工种误配。白名单由 **100 对人工盲标**校准（docs/标注任务.md 任务包）；
2. **负采样**（rel=0）：该 JD 下非正样本随机抽 5×正样本数，固定 seed=42 可复现；
3. **人工抽检（制度化，双工具）**：`tools/eval/spotcheck_gold.py` 全量正样本依据表（程序复核须 0 无法复现）+ `tools/eval/check_human_labels.py` 人工盲标对账（100 对，一致率验收线 ≥95%）——v2.1 实测：程序复核 118 对 0 无法复现；人工一致率 **98.4%**（63/64，唯一分歧为"运维SRE岗×C++开发简历"灰区），达标。人工标注基于 v2.1 金标准抽样；T35 扩库后未重抽（判定规则未变，人工校准结论继续适用于三层判定规则本身），队友如需可按新金标准重抽样；
4. 产物：`backend/tools/eval/gold.jsonl`，每行 `{"jd_id", "resume_id", "rel": 0|1}`。
   当前版本（v4，T36）：**8142 对 / 正样本 1357 / 覆盖 46 个 JD 查询**，评测语料 = **1062 份简历**（512 规范模板 + 550 口语化跨行业，千级语料）× **55 条详细 JD**（30 通用岗位 + 15 行业岗位 + 10 资深/初级变体岗）。程序复核 1357 对 0 无法复现；全库 1062 份审计 0 无依据实体。数据仓库工程师、硬件测试工程师等 9 个 JD 因库内确无对口简历退出查询集。

## 6. 指标公式

| 指标 | 公式/口径 | 用途 |
|---|---|---|
| 实体级 F1 | P=R=TP/(TP+FP+FN)，精确匹配（§2.4） | NER 质量 |
| NDCG@K | 二值增益：`DCG=Σ rel_i/log2(i+1)`，i 从 1 起；IDCG 为理想排序 | 排序质量（主指标） |
| 延迟 | P50 / P95；口径1=单份简历解析+抽取；口径2=单次匹配任务全流程 | 性能 |
| 成本 | DeepSeek 按调用次数×单价估算；本地模型计 0 | 对比报告 |

## 7. 对比实验协议（M04；T34 起四组）

**同测试集、同金标准、固定 seed，唯一变量是方法**：

| 组 | 方法 | 入口 |
|---|---|---|
| 本文方法 | BERT 语义 + 关键词重排融合（§3.2b） | `svc/lexical.py` + `svc/ranking.py hybrid_rank` |
| 消融 | 纯 BERT 语义匹配（本文方法去掉重排层） | `svc/embedding.py` + `svc/ranking.py cosine_rank` |
| 编码器消融（T36） | 同"消融"组，唯编码器不同：底座 bert-base-chinese → DAPT bert_domain → 对比微调 bert_pair | `run_experiments.py` `ABLATE_ENCODERS="标签=模型路径,..."` |
| 对照组一 | TF-IDF + 余弦 | `tools/baselines/tfidf_baseline.py` |
| 对照组二 | DeepSeek 零样本打分 | `tools/baselines/deepseek_zeroshot.py`（`SKIP_DEEPSEEK=1` 可跳过） |

- 红线复查：实验后跑 TC-API-01（grep 证明 `backend/app/` 无外部 API 调用）。

### 7.1 对比微调（T36 B2，`tools/train_contrastive.py`）

- **监督信号**：文件名角色 = 免费标签（§5 同源），简历结构化文本（§3.1 v2）↔ 其角色的训练用 JD 描述构成正对；35 个角色各写一段独立描述（脚本内 `ROLE_JDS`），**与库内评测 JD 无文案复制**——训练中模型从未见过评测 JD 原文（防泄漏）；
- **损失**：MultipleNegativesRanking 思路的批内负样本（对称 InfoNCE，温度 0.05），mean pooling 与线上一致；**批内角色互不重复**（35 角色 > batch 32），避免"同角色不同简历"沦为假负例污染损失；
- **实现**：原生 transformers 手写损失（本机被 sentence-transformers 弄坏过环境，不复用）；起点 = DAPT 模型 `models/bert_domain`，产物 `models/bert_pair/`（含 metrics.json：训练配置与 dev Recall@1 前后对比）；CPU 本机训练；
- **评测口径**：dev 集（按角色分层 8%）做"35 角色 JD 检索 Recall@1"训练自检（0.6667 → 1.0000）；入库效果以 §7 编码器消融（金标准 NDCG）为准；
- **诚实口径（重要）**：角色标签与金标准正样本**同源**（都来自文件名），且训练语料即评测语料库——bert_pair 的 1.0000 属**转导（transductive）设定**，代表"有角色标签时语义空间可被完全对齐"的上限证明，**不代表跨库泛化**；线上主链路仍为 DAPT + 关键词重排（不依赖同库标签），bert_pair 作消融改进项展示。转导成分的量化见 §7.1a 留出法补验。

### 7.1a 留出法补验（T37，`tools/eval/holdout_bert_pair.py`）

**回答"1.0000 里有多少是背题"**：文件名角色配对按角色分层切 85/15（seed=42），只用 85%（902 对）训练对比微调模型（超参与全量训练完全一致，唯一变量是数据切分），金标准正负样本只在 15% 留出池内构造（205 正/1230 对/46 查询，35 角色均有留出），四种编码器在**同一留出子集**上对比（候选池=仅留出 160 份）：

| 编码器 | NDCG@10 | P@5 | 口径 |
|---|---|---|---|
| 底座 bert-base-chinese | 0.8524 | 0.7174 | 下限 |
| DAPT(bert_domain) | 0.8761 | 0.7565 | 线上主链路 |
| bert_pair 全量 | 0.9998 | 0.8870 | 转导对照（见过留出池） |
| **bert_pair 留出** | **0.9929** | **0.8826** | **真泛化（从未见过留出池）** |

**解读**：全量−留出 = 0.007，即 §7 转导口径 1.0000 里"背题"成分**不足 1 个百分点**；留出模型比 DAPT 高 **+0.117**——对比微调学到的是"简历↔岗位描述"的对齐能力而非样本记忆。§7.1 的诚实口径由"上限证明"升级为"泛化已实证"；§7.2 改写考卷上 bert_pair 0.9799 反超 TF-IDF（0.9633）是同一结论的跨语料佐证。线上主链路仍为 DAPT + 关键词重排不变。

### 7.2 改写压力考卷（T37，`tools/eval/stress_eval.py` + `测试简历/generate_stress_resumes.py`）

**动机**：v4 主考卷上本文方法输给 TF-IDF（0.9305 < 0.9898），考卷偏科——模板简历把角色词写在求职意向/职位行里，词面法抓词面是天然强项。为回答"角色词消失时谁还行"，另造**独立小考卷**（不与 v4 混算，避免 >10 正样本稀释 NDCG@10、并控制 DeepSeek 花费）：20 角色 × 8 人 = 160 份口语化散文简历，**正文逐字避开本角色岗位词**（生成时断言：护士不写"护理"、电商运营不写"运营"、金融风控不写"风控/金融"……），角色信号只藏在经历/技能表述里（经历句以工作动词开头，对齐结构化文本 v2 的要点行抽取），文件名保留「姓名_角色.docx」作金标准依据（§5 路径一）。

**金标准**：文件名角色过三层判定，覆盖 29 个 JD 查询（含"前端开发工程师（React方向）"等变体岗经细分白名单层命中），正样本 232（每查询恰 8），负采样 5:1，seed=42。

**结果**（NDCG@10，同一子集同一金标准）：

| 组 | 改写考卷 | v4 主考卷 | 变化 |
|---|---|---|---|
| TF-IDF 基线 | 0.9633 | 0.9898 | 微降 |
| 底座 | 0.8181 | 0.6968 | 上升 |
| DAPT(bert_domain) | 0.8774 | 0.7483 | 上升 |
| bert_pair | **0.9799** | 1.0000（转导） | **首次反超 TF-IDF** |
| 本文方法（语义+重排） | 0.8400 | 0.9305 | 重排层转拖累 |
| DeepSeek 零样本 | **0.9980** | 0.9783 | 最稳（1392 次调用 0 失败） |

**结论（如实）**：①词面法的鲁棒性比预想强——它吃的是**整个领域词汇**而非岗位词（不说"护理"仍会说输液/医嘱/患者，这些词 JD 原文里也有），隐藏岗位词不足以打崩 TF-IDF；②bert_pair 在**从未见过**的改写简历上反超 TF-IDF——考卷生成晚于训练，属跨语料泛化而非转导，是全部实验中语义方法第一次赢词面法，实锤"编码器对齐后语义有上限优势"；③关键词重排层在改写考卷上轻微拖累（DAPT 0.8774→融合 0.8400，JD 标题词真不存在于正文），线上主链路仍以主考卷整体最优（0.9305）口径为准；④DeepSeek 对改写最稳——LLM 语义推理不依赖词面重叠。

### 7.3 半规范考卷（T38，`tools/eval/semispec_eval.py` + `测试简历/generate_semispec_resumes.py`）

**动机**：主卷两档语料（规范模板 / 口语散文）之间，现实中最常见的其实是"半规范中间态"——表格排版、栏目乱序、缺栏目、无栏目流水账。此前版式鲁棒性从未被量过。与 T37 改写考卷互补：那份考**内容**（正文避开岗位词），这份考**版式**（岗位词都在正文里）。

**考卷**：20 角色 × 5 版式 = 100 份独立小考卷（不与主卷混算）：V1 全表格（内容全在 docx 单元格）、V2 栏目乱序（自评→技能→工作→教育、意向沉底）、V3 缺栏目（缺教育+自评）、V4 流水账（无栏目名短行堆叠）、V5 表格+乱序。金标准同 §5 路径一（文件名角色），manifest 带 `layout` 标签可按版式分解。

**结果**（NDCG@10，同一池同一金标准，`docs/eval/semispec_report.json`）：

| 组 | 半规范考卷 | 按版式分解（乱序 / 流水账 / 缺栏目 / 表格乱序 / 表格） |
|---|---|---|
| TF-IDF 基线 | 0.9918 | 1.000 / 1.000 / 1.000 / 1.000 / 0.987 |
| 底座 | 0.9382 | 0.987 / 0.975 / **0.945** / 0.975 / 0.987 |
| DAPT(bert_domain) | 0.9807 | 1.000 / 1.000 / **0.945** / 1.000 / 1.000 |
| bert_pair | **1.0000** | 全版式 1.000 |
| 本文方法（固定 α=0.7） | 0.9592 | 0.987 / 1.000 / 0.970 / 1.000 / **0.957** |
| DeepSeek 零样本 | **1.0000** | （870 次调用 0 失败） |

**结论（如实）**：①版式鲁棒性整体好于预期——解析器本就覆盖表格单元格与文本框（S01），NER 走行级流水线对乱序天然免疫，DAPT 纯语义除缺栏目外全版式 1.000，说明**真正伤系统的是"内容缺失"而非"排版花哨"**（缺栏目版无教育/自评可抽，实体锚点变薄：100 份 title 抽出 97/100、skill 仅 74/100——skill 缺口是词典覆盖差异，正是要量的现实）；②重排层在**表格版**上转拖累（DAPT 1.000 → 融合 0.957）：表格简历的词面覆盖率被压低，与 §7.2 改写考卷的拖累是同一机理在"版式维"的复现——两份独立考卷共同指向"词面证据稀薄时固定 α 有害"，§7.4 自适应 α 在本考卷 0.9592→0.9826 回收即为对策实证；③bert_pair 跨语料泛化再次满分的第三次复现（主卷转导 1.0000 → 改写 0.9799 → 半规范 1.0000），对比微调学到的对齐能力对内容与版式两种分布外都稳；④DeepSeek 连续三卷 0 失败且本卷满分，LLM 对照组稳定性最省心。

### 7.4 自适应 α 验证（T39/B2，`tools/eval/adaptive_alpha_check.py`）

**设计**：§3.2b 自适应 α 规则零自由参数（coverage 阈值 0.5 沿用中性值约定），方向由 §7.2 拖累现象启发。验证三问：主卷动不动？压力卷救不救？考卷间是否方向一致？同一 DAPT 编码上三池对比（`α_eff = 0.7 + 0.3·(1−coverage)` 逐 JD 计算）：

| 池 | 纯语义(α=1) | 固定 α=0.7 | 自适应 α | coverage 均值 |
|---|---|---|---|---|
| v4 主卷（1062 份，冻结金标准） | 0.7483 | 0.9305（复现✓） | **0.9522**（+0.0217） | 0.056 |
| 压力考卷（160 份） | 0.8774 | 0.8400（复现✓） | **0.8589**（+0.0189） | 0.019 |
| 半规范考卷（100 份） | 0.9807 | 0.9592 | **0.9826**（+0.0234） | 0.042 |

**结论（如实）**：①复现断言双过——v4 池由"全库 − 压力 − 半规范 manifest"精确重建 1062 份，固定 α 在冻结金标准上精确复现 0.9305/0.8400，证明重建池=冻结池、开关基线无漂移；②三池全部向好且幅度一致（+0.019~+0.023）——固定 α=0.7 是在**全池平均**意义下调的，逐 JD 的词面证据可得性差异很大（覆盖率 2%~6%，多数 JD 词面证据稀薄），按 JD 自适应比全局定一个 α 更合理；③主卷也涨 2.2pp 是计划外的正收益（原本只求"不动"），侧面说明 §3.2b α 扫描"0~0.9 全持平"的平坦性掩盖了逐 JD 异质性；④默认值据此定为**开**（`MATCH_ADAPTIVE_ALPHA=1`），离线 harness 保持固定 α 口径使冻结数字可复现。诚实口径：规则虽零参数，但"用 coverage 调 α"这一方向本身是看完三池现象后定的，留待未来真正独立语料再验。
