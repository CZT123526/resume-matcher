# 人工标注任务（T33 前置：评测金标准的人工确认）

> 交给队友的任务说明，读完这一页就能开工，预计 **每人 30~40 分钟**。
> 不需要装任何环境、不需要跑代码，用 Excel / WPS 打开一个 CSV 填一列就行。

---

## 1. 我们要你干什么

打开 **`docs/eval/human_labels.csv`**，一共 **100 行**，每行是一对「岗位 JD + 简历」。
你只需要假装自己是 HR，对每一行判断：

> **"这份简历投这个岗位，我会不会让他进面试？"**
> 会 → 填 **1**（相关）；不会 → 填 **0**（不相关）；实在拿不准 → **留空**（不算错）。

只填 **「你的判定」和「标注人」** 两列（备注可选），其他列不要动。

## 2. 判定标准（就这三条）

1. **岗位方向要对得上**：Java 后端岗 vs Python 后端简历——语言栈明显不同就算 **0**；
   「新媒体运营」岗 vs「新媒体内容运营」简历，方向一致算 **1**。
2. **别想太多**：这是课程项目的评测数据，不是真招聘。按第一直觉判，单行别超过 30 秒。
3. **拿不准就留空**：空着比乱填好，乱填会污染我们的统计。

不需要你看懂系统内部怎么算的——**你的直觉就是标准答案的来源**，这正是这个任务的价值。

## 3. 为什么需要这个（给队友的背景，30 秒版）

系统的评测金标准目前是**规则自动生成**的（按简历文件名里的岗位角色 + 技术栈冲突检查）。
规则对不对，需要一批**人肉判断**来对账：

- 人工和规则**一致率高**（≥95%）→ 证明金标准可信，冻结的实验数字站得住；
- **分歧多** → 说明规则有漏洞，我们先修规则再谈提高模型。

所以：**请独立判断，不要先去看 gold.jsonl 或任何代码里的答案**（盲测才有效）。

## 4. 分工建议

100 行 ÷ 3 人 ≈ 每人 33~34 行。在「标注人」列写你的名字/昵称即可，按行号分段领：
比如 A 领 P001~P034、B 领 P035~P067、C 领 P068~P100。谁先干完可以多领。

## 5. 干完怎么交

- 会 git 的：把填好的 CSV 放回原路径，直接提 PR（标题：`docs: 人工标注结果`）；
- 不会 git 的：把 CSV 发到群里，由组长统一放回来。

## 6. 交回来之后会发生什么（系统自动核对）

仓库里已备好核对脚本，一条命令出报告：

```bash
cd backend && python tools/eval/check_human_labels.py
```

输出：每人的填写数、人工 vs 规则金标准的一致率、全部分歧明细清单
（写入 `docs/eval/human_check_report.md`）。一致率达标即关闭本任务。
