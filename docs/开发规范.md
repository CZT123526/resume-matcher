# 开发规范

> 三人协作的"交通规则"。开工前每人读一遍；PR 不符合本规范的直接打回。

## 1. 三层契约（面向接口编程的落地）

| 层 | 契约 | 载体 | 谁消费 |
|---|---|---|---|
| HTTP 接口契约 | 有哪些接口、什么行为 | `docs/backend-api.md` + `docs/api-schemas.md` | 前端 ↔ 后端 |
| 数据契约 | 每个字段的类型/约束 | `backend/app/schemas/*.py`（Pydantic） | api 层 ↔ svc 层 ↔ 前端 |
| 服务契约 | svc 函数签名与语义 | `backend/app/svc/contracts.py`（S01–S11） | 后端各模块之间 |

**变更流程（契约先行）**：改文档/契约代码 → PR 评审通过 → 再改实现 → 更新状态表。
禁止"实现先行、文档后补"。

## 2. 分层规则（红线条目）

```
api/   只做：参数校验(schemas)、调 svc、组装包裹响应。禁止写业务逻辑、禁止直接碰 DB。
svc/   业务与算法。禁止 import fastapi、禁止任何外部 HTTP API 调用。
tools/ 离线脚本（训练/评测/DeepSeek 基线）。禁止被 app/ import（评审检查项）。
```

- svc 层抛 `AppError`，api 层**不写 try/except**（main.py 全局处理器统一转换）。
- 禁止手写 `HTTPException`。

## 3. 文件组织与命名

- 新功能 = `svc/xxx.py` + `tests/test_xxx.py` 成对出现；路由在 `api/` 里按资源分文件注册。
- Python：文件/函数 `snake_case`，类 `PascalCase`；前端组件 `PascalCase.jsx`，hooks `useXxx`。
- 常量全大写；魔法数字一律提成常量并注释。

## 4. Git 工作流

- `main` 受保护（不直接 push）；功能分支命名 `feat/m01-upload-api`、`fix/evidence-dedupe`、`docs/algorithm-design`。
- commit 格式：`类型(范围): 中文描述`，类型 = feat/fix/docs/refactor/test/chore。
- **PR 模板**（建 PR 时粘进描述）：

```markdown
### 改动点
- 
### 自测
- [ ] pytest 通过（本地跑过）
- [ ] 前端 npm run build 通过（若动了前端）
- [ ] 冒烟：上传/匹配主流程可用（若动主流程）
### 契约
- [ ] 改了 backend-api.md / api-schemas.md / contracts.py？（改了须在改动点列出）
### 状态表
- [ ] docs/status/ 对应行已更新（含 commit 短哈希+日期）
```

- **Review 清单**（评审人 5 分钟过一遍）：
  1. 分层越界？（api 写业务 / app 里 import tools / 外部 API 调用）
  2. 契约同步？（接口变更三处：文档、schemas、前端调用）
  3. 测试覆盖？（新函数有对应 test 文件）
  4. 敏感信息？（.env、密钥、绝对路径）

## 5. 前后端并行开发（mock 方案）

后端接口没好时前端不等待：

1. `frontend/src/mocks/` 下按接口路径建 fixtures（如 `resumes.list.json`），内容抄本文档示例；
2. `frontend/src/api.js` 封装统一 fetch：`VITE_USE_MOCK=true` 时读 fixtures，否则走 `/api`；
3. mock 数据字段必须与 `api-schemas.md` 完全一致——联调时删掉开关即可切换，不许改组件代码。

## 6. DoD（完成的定义）

一条任务只有全部满足才算"已完成"（状态表可改）：

- [ ] 单测覆盖且 pytest 全绿
- [ ] 构建/启动通过（后端 uvicorn 可起、前端可 build）
- [ ] 冒烟走通受影响的主流程
- [ ] 契约文档与代码一致
- [ ] 状态表已更新（编号|名称|说明|负责人|状态|备注：commit+日期）
- [ ] PR 合并进 main

## 7. 安全与配置基线

- `.env` 永不入库；新增配置必须同步 `.env.example`（带注释）。
- 上传文件：白名单后缀 + 大小校验 + 服务端重命名存储，禁止路径拼接用户输入。
- 依赖只进 `requirements.txt` / `package.json`，不用全局安装替代。
- 日志不含个人信息（姓名/电话），前端展示姓名可后端脱敏开关预留。

## 8. 性能预期（写代码前对齐的量级）

| 操作 | 预期 | 超标动作 |
|---|---|---|
| 单份简历解析+抽取 | ≤ 3s（CPU） | 查 NER 批量是否生效 |
| 万级简历建向量缓存 | ≤ 10 min | 批量大小调优，禁止逐条 |
| 单次匹配（含读缓存+排序） | ≤ 1s | 查是否意外重建了缓存 |
| 列表接口 | ≤ 200ms | 检查分页与大字段（raw_text 不进列表） |
