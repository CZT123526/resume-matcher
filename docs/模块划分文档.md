# 模块划分文档

> 本文档是团队"取号"开发的唯一依据：认领模块 = 在 [status/modules.md](status/modules.md) 把自己写进负责人列。
> 优先级：P0 = 初期检查必须 ｜ P1 = 中期检查必须 ｜ P2 = 有余力再做。

## 模块总览

| 编号 | 模块 | 包含接口/服务 | 优先级 | 负责人 | 状态 |
|---|---|---|---|---|---|
| M01 | 简历上传与解析（解析Agent） | `POST /api/resumes/upload`、`GET /api/resumes`、`GET /api/resumes/{id}`、`DELETE /api/resumes/{id}`；S01、S02 | P0 | 成员B | 未开始 |
| M02 | 数据管道与实体抽取模型 | `POST /api/admin/distill`、`GET /api/model/info`；S04~S08 | P0 | 成员A | 未开始 |
| M03 | 岗位-候选人匹配（含调度Agent） | `POST /api/jds`、`GET /api/jds*`、`POST /api/match-tasks`、`GET /api/match-tasks*`；S09~S11 | P0 | 成员B | 未开始 |
| M04 | HR交互与可视化前端 | 上传页、JD对话页、候选人排名卡片、证据链展示 | P0 | 成员C | 未开始 |
| M05 | 评估报告生成与导出 | `GET /api/reports/{task_id}/export`；S12 | P1 | 成员A | 未开始 |
| M06 | Docker容器化与一键部署 | Dockerfile、docker-compose.yml、Nginx配置 | P1 | 成员C | 未开始 |
| M07 | 登录与权限（预留） | `POST /api/auth/*`、users 表启用 | P2 | 成员C | 未开始 |
| M00 | 工程基础设施 | 仓库骨架、/health、测试与冒烟、文档体系 | P0 | 成员B | **已完成** |

## 模块间依赖关系

```
M02(数据/模型) ──供模型──> M01(解析) ──结构化入库──> M03(匹配) ──排名结果──> M04(前端展示)
                                   M03 证据链 ──> M05(报告)      M06(部署) 打包 M01~M05
```

- M01 依赖 M02 的 S03(LLM封装)与 S06(BERT抽取，可后接)：先接 LLM 抽取跑通，BERT 作为可替换实现
- M03 依赖 M01 的结构化数据 + M02 的 S07/S08(向量检索)
- M04 依赖 M01/M03 的接口契约（见 [backend-api.md](backend-api.md)），可并行开发（mock 数据先行）

## 分工基准（3人）

| 成员 | 主责模块 | 说明 |
|---|---|---|
| 成员A | M02、M05 | 数据管道、蒸馏训练、向量库、报告 |
| 成员B | M01、M03、M00 | 后端API、三个Agent、工程纪律维护 |
| 成员C | M04、M06、M07 | 前端全部页面、容器化部署 |
