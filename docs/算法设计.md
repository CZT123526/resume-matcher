## 1. 统一抽取 Schema（7 类实体）

BERT NER 的输出、entities 表的 field_key、前端展示共用这一套字段，**任何一方不得私加字段**：

| field_key | 含义 | 规范化规则 | 示例 |
|---|---|---|---|
| `name` | 姓名 | 原样保留，长度 2~4 优先 | 张三 |
| `degree` | 学历 | 枚举归一：`大专/本科/硕士/博士`（别名表见 ner_rules；判不出的值直接丢弃，不再归一为"其他"——T29.2：实体必须有原文依据） | 硕士 |
| `school` | 毕业院校 | 原样保留（别名归一留给 P2，不做有损处理） | 华中科技大学 |
| `skill` | 技能 | 小写、去空格；同义合并（py→python） | python |
| `years` | 工作年限 | 归一为数字字符串（"三年"→"3"） | 5 |
| `company` | 任职公司 | 去括号备注；校名结尾的值丢弃（教育机构被 BERT 误标成公司——T30.3） | 腾讯 |
| `title` | 职位 | 原样保留；去 BERT 插入空格；政治面貌/语言等级黑名单丢弃（T30.2）；**项目栏目与项目头行（破折号+竖线+日期段）里的 title 标注丢弃**——项目名/项目内角色不是求职岗位（T30.3）；求职意向行无已知后缀时按锚定模式抽取 | 后端开发工程师 |

- 同一字段多值时输出多条记录（如多个 `skill`），不做合并存储。
- NER 没抽到的字段**不输出**空记录。

## 2. NER 方案（S02/S03）

### 2.1 标注体系

- 标注格式：**BIO**，标签集 = 7 实体 × {B,I} + O = 15 个标签。
- 数据集：公开**中文简历 NER 标注集**为主（约 3000 份简历、句级样本数万条，满足"训练样本 ≥ 1 万"口径——口径按**句级训练样本**计，不是简历份数）。
- 数据集标签 → 本项目 7 字段的映射表在 `backend/tools/data/label_mapping.py` 中以字典显式维护，映射不到的标签丢弃并记录丢弃数。
- CLUENER2020（约 1.2 万条）：**不做标签迁移**（实体体系与简历域不同），仅可选用于底座继续预训练；时间不够直接放弃，不阻塞主线（见 technical.md D7）。

### 2.2 长文本处理

简历全文远超 BERT 上限，采用**句级流水线**：

1. 训练：简历按行/标点切句，句级 BIO 标注，`max_len=256`；
2. 推理：同样切句逐批编码，实体按 `(句id, 字段)` 聚合，同字段同值去重。

### 2.3 训练配置（Colab T4 实测可承受）

| 项 | 值 |
|---|---|
| 底座 | bert-base-chinese |
| 任务头 | 线性分类头（token 级，num_labels=15） |
| 优化器 | AdamW，lr=2e-5 |
| batch / epoch | 16 / 4 |
| max_len | 256 |
| warmup | 前总步数 10% 线性 warmup |
| 随机种子 | 42（写死，保证可复现） |
| 产物 | `backend/models/ner/`（不入库，.gitignore） |

### 2.4 指标口径

**实体级精确匹配**：预测实体的 `(字段, 值, 文本位置)` 全对才算 TP。

- P = TP / (TP + FP)，R = TP / (TP + FN)
- F1 = 2·P·R / (P + R) = 2·TP / (2·TP + FP + FN)

报告 P/R/F1 三个数。

## 3. 语义匹配（S05/S06）

### 3.1 编码对象

| 对象 | 编码文本 |
|---|---|
| JD | S04 抽出的要求 + JD 原文前 500 字，拼接 |
| 简历 | **结构化拼接文本**：技能 + 职位 + 公司/经历行（由 entities 表拼接生成），不用全文 |

> 理由：全文含大量噪声（格式、联系方式）；结构化拼接让匹配对齐"岗位要求 ↔ 能力事实"。

### 3.2 向量与相似度

- 底座：同一个微调后 BERT（D5，NER 底座复用），取**最后层 mean pooling**（[CLS] 作为消融实验项）；
- 向量 L2 归一化后，余弦相似度 `cos ∈ [-1,1]`，线性归一 **`score = (1 + cos) / 2 ∈ [0,1]`，保留 4 位小数**；
- 排序按 score 降序取 top_k（默认 10，上限 50）。

### 3.3 向量缓存（vectors.npy）

- 文件：`db/vectors.npy`（矩阵，行序对应 `db/resume_ids.json` 的 resume_id 列表）；
- 重建规则：简历新增/删除/重新解析 → 标记缓存失效 → **全量重建**（万级简历 CPU 重编码 < 10 分钟，可接受；不做增量，降低复杂度）；
- 重建入口只在解析流水线末尾调用，匹配任务只读缓存。

## 4. 证据链规则（S07）——打分与解释分离

**红线：证据链只解释分数，绝不参与打分。** 否则规则改动会污染三组模型的对比公平性。

```
输入: jd_reqs = S04(JD), ents = S02(简历)
输出: evidence[] (文本数组，文案格式定稿如下，前端原样展示)

1. 技能交集: S_jd ∩ S_resume
   → 非空: "技能重叠：Python/FastAPI (2/2)"
   → jd 有简历无: "缺少技能：Docker"
2. 学历比较: rank(degree) ∈ {大专0, 本科1, 硕士2, 博士3}
   → 满足: "学历满足：硕士≥本科" / 不足: "学历不满足：本科<硕士" / 缺失: "学历：未识别"
3. 年限比较: years(简历) ≥ min_years(JD)
   → "经验满足：5年≥3年" / "经验不足：1年<3年" / "经验：未识别"

格式约定: 全角冒号；计数用 (n/m)；比较式直接给结论。
```

## 5. 金标准构造（评测 ground truth，D6）

简历库自带的期望岗位字段是免费的监督信号：

1. **正样本对**：简历的期望岗位/目标职位 → 与对应岗位的 JD 配对，rel=1；
2. **负采样**：随机抽其它 JD 配对，rel=0，正负比 1:5（固定 seed=42 可复现）；
3. **人工抽检**：随机抽 100 对人工核对，噪声率目标 < 5%；超标则修构造规则重建金标准；
4. 产物：`backend/tools/eval/gold.jsonl`，每行 `{"jd_id", "resume_id", "rel": 0|1}`。

## 6. 指标公式

| 指标 | 公式/口径 | 用途 |
|---|---|---|
| 实体级 F1 | P=R=TP/(TP+FP+FN)，精确匹配（§2.4） | NER 质量 |
| NDCG@K | 二值增益：`DCG=Σ rel_i/log2(i+1)`，i 从 1 起；IDCG 为理想排序 | 排序质量（主指标） |
| 延迟 | P50 / P95；口径1=单份简历解析+抽取；口径2=单次匹配任务全流程 | 性能 |
| 成本 | DeepSeek 按调用次数×单价估算；本地模型计 0 | 对比报告 |

## 7. 三组对比实验协议（M04）

**同测试集、同金标准、固定 seed，唯一变量是方法**：

| 组 | 方法 | 入口 |
|---|---|---|
| 本文方法 | BERT 语义匹配 | `svc/embedding.py` + `svc/ranking.py` |
| 对照组一 | TF-IDF + 余弦 | `tools/baselines/tfidf_baseline.py` |
| 对照组二 | DeepSeek 零样本打分 | `tools/baselines/deepseek_zeroshot.py` |

- 统一入口 `backend/tools/run_experiments.py`，产出 `metrics.json` + 图表到 `docs/eval/`；
- DeepSeek：带重试（3 次退避）+ 结果缓存（jsonl 去重）；单条失败记 None 不中断；
- 红线复查：实验后跑 TC-API-01（grep 证明 `backend/app/` 无外部 API 调用）。

## 8. 风险与降级预案

| 风险 | 信号 | 降级方案 |
|---|---|---|
| NER F1 低 | < 0.80 | 学历/年限用正则规则兜底（source 标记 rule），BERT 只负责技能/职位 |
| 匹配效果差 | NDCG@10 < 0.7 | 调负采样比；换 [CLS]/mean pooling；加关键词重排层 |
| Colab 断连 | 训练中断 | checkpoint 每 epoch 保存到 Drive；seed 固定可续训 |
| DeepSeek 不稳定 | 超时率高 | 对照组二标注"部分数据缺失"，不影响主线结论 |
